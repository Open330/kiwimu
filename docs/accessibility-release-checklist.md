# 접근성 출시 검증 체크리스트

자동화 검사는 명백한 회귀를 빠르게 찾는 게이트이고, 스크린리더가 전달하는 의미·순서·피로도까지 보장하지는 않습니다. 아래 수동 행렬을 정식 출시 후보 빌드에서 실제로 듣고 완료해야 합니다.

## 자동 게이트

`bun run test:e2e`가 다음 항목을 검증합니다.

- axe serious/critical 위반 없음
- Chromium accessibility tree의 landmark, 이름, 역할
- skip link, 검색, 모바일 메뉴, 퀴즈의 키보드 흐름과 focus 이동
- `prefers-reduced-motion`에서 즉시 이해 가능한 퀴즈 전환
- `forced-colors`에서 skip link의 focus indicator가 보이는지 확인하는 smoke test

자동 결과만으로 아래 수동 sign-off를 완료 처리하지 않습니다.

## 필수 수동 행렬

| 환경 | 최소 범위 | 결과 | 검사자 / 날짜 | 이슈 링크 |
|---|---|---|---|---|
| macOS 최신 안정판 + VoiceOver + Safari | 전체 시나리오 | 미검사 |  |  |
| Windows 최신 안정판 + NVDA 최신판 + Firefox | 전체 시나리오 | 미검사 |  |  |
| Windows 최신 안정판 + NVDA 최신판 + Chrome | 핵심 시나리오 | 미검사 |  |  |

`결과`는 `통과`, `조건부 통과`, `실패` 중 하나로 바꾸고 검사자·날짜와 발견 이슈를 반드시 기록합니다.

## 전체 시나리오

화면은 보지 않거나 가린 상태에서 키보드와 스크린리더 명령만 사용합니다.

1. 홈에서 문서 제목, 주요 메뉴, 문서 탐색, 본문 landmark가 중복되거나 모호하지 않게 발표되는지 확인합니다.
2. 첫 Tab으로 "본문으로 건너뛰기"를 실행하고 focus가 본문에 도착하는지 확인합니다.
3. 검색을 열고 검색어를 입력한 뒤 결과 수 변화, 위/아래 이동, 선택 항목, Escape 닫힘이 발표되는지 확인합니다.
4. 문서 링크 미리보기를 열고 dialog/region 맥락, 제목, 닫기 동작, 원래 focus 복귀를 확인합니다.
5. 문서 편집 dialog에서 제목, textarea, 상태 메시지, 저장 오류/성공, Escape 닫힘과 focus 복귀를 확인합니다.
6. 퀴즈에서 현재 문제·전체 문제 수, 입력/선택 컨트롤, 정오답, 해설, 다음 문제 focus, 최종 점수를 확인합니다. 숨겨진 카드 면이 탐색되지 않아야 합니다.
7. 그래프에서 시각적 노드 대신 제공되는 설명과 확대/축소 컨트롤 이름을 확인합니다. 그래프만으로 전달되는 필수 정보가 없어야 합니다.
8. 카탈로그·출처·활동 표/목록에서 제목과 필터 상태, 표 header 관계, 결과 없음 상태를 확인합니다.
9. 관리 화면에서 모든 입력의 label·hint·오류가 연결되고, API 키가 불필요하게 읽히지 않는지 확인합니다.

## 판정 기준

- 차단: 기능을 완료할 수 없음, focus 유실/함정, 이름 없는 핵심 컨트롤, 상태가 발표되지 않음, 숨김 콘텐츠가 읽힘
- 출시 전 수정: 순서가 혼란스러움, 중복 발표, heading/landmark 구조 오류, 오류 복구가 불명확함
- 후속 개선 가능: 기능 완료에는 영향이 없는 장황한 표현이나 경미한 탐색 비효율

차단 또는 출시 전 수정 항목이 하나라도 열려 있으면 접근성 sign-off는 완료가 아닙니다.

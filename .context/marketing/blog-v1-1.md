# 위키는 만드는 게 아니라 자라는 거였다 — kiwimu v1.1 5가지 변화

> kiwimu v1.0을 공개한 지 한 달. 피드백을 모으고, 직접 써보면서 "이게 진짜 필요한 방향이다" 싶은 것들을 골랐습니다. v1.1은 한 문장으로 요약하면: **위키가 알아서 자라도록 만든 업데이트**입니다.

---

## 0. kiwimu가 뭔데?

kiwimu는 문서(PDF, DOCX, URL, Markdown)를 넣으면 LLM이 개념을 추출해서 interlinked learning wiki로 바꿔주는 CLI 도구입니다.

```
bunx @open330/kiwimu init --demo
```

셀프호스팅, MIT 라이선스, 텔레메트리 없음. 30초면 데모를 볼 수 있습니다.

v1.0에서 "문서를 넣으면 위키가 된다"를 증명했다면, v1.1은 **위키가 스스로 성장하는 구조**를 만들었습니다.

---

## 1. 출처 추적 (Provenance Tracking)

AI가 만든 위키의 가장 큰 약점: **"이 내용 어디서 나온 거야?"**

v1.1부터 모든 AI 생성 문장에 인라인 인용이 자동으로 붙습니다.

```markdown
AVL 트리의 높이는 항상 $O(\log n)$을 보장합니다.[^src:이진탐색트리]
```

`[^src:slug]` 형태로 원본 페이지를 직접 가리킵니다. 클릭하면 원본으로 점프. 출처 커버리지 행렬도 함께 제공해서 "어떤 페이지는 AI만 쓰고 원본 인용이 없는 상태"도 한눈에 파악할 수 있습니다.

**왜 중요하냐면:** AI가 만들어준 위키를 팀에서 실제로 쓰려면 신뢰가 필요합니다. 출처가 없으면 "그냥 AI가 지어낸 거 아니야?"라는 의심이 생기고, 그 위키는 죽은 문서가 됩니다.

---

## 2. 스키마 레이어 (Schema Layer)

kiwi.toml에 5줄이면 LLM이 따라옵니다.

```toml
[schema]
categories = ["개념", "알고리즘", "자료구조"]
page_template = "concept"
style = "academic"
max_length = 300
```

팀의 용어, 카테고리, 페이지 템플릿을 정의하면 LLM이 그 틀 안에서만 작동합니다. "우리 팀은 '개념'과 '알고리즘' 두 카테고리만 쓴다", "페이지는 항상 300자 이내로 써라" 같은 규칙을 코드로 강제할 수 있습니다.

**왜 중요하냐면:** 위키가 커지면 일관성이 무너집니다. 사람이 관리하면 지치고, LLM에 맡기면 제멋대로가 됩니다. 스키마가 그 사이를 잡아줍니다.

---

## 3. 질문 → 위키 승격 (Query → Wiki Promotion)

이건 v1.1의 **킬러 피처**입니다.

1. 위키 페이지 본문에서 모르는 문장을 드래그합니다
2. 팝오버가 뜨면 질문을 입력합니다
3. AI가 답변을 생성합니다
4. **"위키에 저장"** 버튼을 누르면 정식 위키 페이지가 됩니다

중복 자동 감지가 있어서 이미 비슷한 개념 페이지가 있으면 기존 페이지에 내용을 추가합니다.

```javascript
// 프로모트 API
POST /api/promote
{
  "question": "회전 연산이란?",
  "answer": "...",
  "title": "트리 회전 (Tree Rotation)",
  "sourcePageId": 42,
  "selectedText": "회전(rotation) 연산을 통해"
}
```

**왜 중요하냐면:** 위키를 처음부터 "만드는" 것은 어렵습니다. 하지만 읽다가 모르는 게 생기면 "이거 궁금한데" 하고 드래그하는 건 자연스러운 행동입니다. 그 자연스러운 행동이 위키 페이지가 되는 것. 이게 kiwimu의 핵심 아이디어입니다.

---

## 4. 콘텐츠 카탈로그 (/catalog)

100개 페이지에서도 길을 잃지 않습니다.

`/catalog` 페이지에서 모든 위키 페이지를 카테고리별로 볼 수 있습니다. 자동으로 카테고리가 분류되고, 각 페이지의 출처 커버리지 상태도 함께 보여줍니다.

검색이 아니라 **발견**이 가능해집니다. "우리 위키에 자료구조 관련 페이지가 뭐가 있지?"라고 물었을 때, 검색창에 키워드를 치는 게 아니라 카탈로그를 스크롤하면 답이 나옵니다.

---

## 5. 활동 로그 (Activity Log)

모든 작업이 시간선으로 누적됩니다.

- 위키 페이지가 언제 생성되었는지
- 어떤 질문이 들어왔는지
- 프로모트가 언제 일어났는지
- 스키마가 언제 변경되었는지

"보이지 않는 진척은 없는 진척입니다." 팀 위키가 실제로 쓰이고 있는지, 어디서 막히고 있는지를 활동 로그로 확인할 수 있습니다.

---

## 6. 트랙 그룹핑 (Track Grouping)

100페이지 위키에서도 길을 잃지 않는 두 번째 장치.

`kiwi.toml`에 트랙(track)을 정의하면, 사이드바와 인덱스가 자동으로 그 그룹별로 묶여서 표시됩니다. 카테고리 필터링이 아닌 **위키 자체의 정보 구조를 트랙으로 표현**하는 방식입니다.

```toml
[tracks]
"입문" = ["자료구조-입문", "알고리즘-기초"]
"심화" = ["고급-자료구조", "그래프-알고리즘"]
```

검색에 의존하지 않고도 학습 경로가 보입니다.

---

## 7. 인증 토큰 영속화

작은 변화지만 매번 마찰을 만들던 부분.

v1.0에서는 `kiwimu serve` 재시작할 때마다 새 인증 토큰이 발급되어, 관리 페이지나 동적 Q&A를 다시 인증해야 했습니다. v1.1부터는 토큰을 디스크에 저장하고 쿠키로 받아서, **한 번 로그인하면 재시작해도 그대로 유지**됩니다.

`KIWI_AUTH_TOKEN` 환경변수로 직접 지정도 가능합니다 (CI/배포 환경용).

## 다음은?

v1.1은 "위키가 자라나는 구조"를 만든 업데이트입니다. 다음 버전에서는:

- **퀴즈 시스템 고도화**: SM-2 간격 반복 학습 + 퀴즈 자동 생성
- **지식 그래프 시각화**: 페이지 간 연결 관계를 그래프로 표현
- **멀티모달 입력**: 이미지, 영상에서 개념 추출

셀프호스팅 위키가 "만들어지는 게 아니라 자라는 것"이 되는 그날까지.
